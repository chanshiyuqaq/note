- 下面代码是使用广度优先的思想实现的二叉树的层次遍历
``` cpp
class Solution {
public:
    vector<vector<int>> levelOrder(TreeNode* root) {
        //广度优先搜索转化的 ---> 层次遍历
        queue<TreeNode*>q;
        q.push(root);
        vector<vector<int>>res;
        if(root == nullptr) return res;
        while(!q.empty())
        {
            int num = q.size();
            vector<int>cur_row;
            for(int i = 0 ; i<num;i++)
            {
                
            auto cur = q.front();
            q.pop();
            cur_row.push_back(cur->val);
            if(cur->left!=nullptr){q.push(cur->left);}
            if(cur->right!=nullptr){q.push(cur->right);}
            }
            res.push_back(cur_row);
        }
        return res;
    }
};
```

最小生成树：

算法导论部分：
- 生成数：包含全部顶点，连通的子图
- ==多条边权相同==可能得到不同形状，但是总权值相同的MST
- 维护一个边集，不断往里面放安全边，直到n-1条
- Kruskal按边权选择
- Prim选点，每次选连接已经选边集和未选边集最小的边
- 割是将点划分为两组，边的两个顶点一个在A组一个在B组，则这个边跨越割
- 一个割尊重边集A指的是边集A中==没有跨越割的边==
- 在所有跨越割的边中权值最小的，叫做轻边
- 定理
	- A 是某棵 MST 的子集
	- 割 (X,Y) 尊重 A
	- 边 (u,v) 是横跨割 (X,Y) 的一条轻边
	- 则边是安全边 

K算法的思想：
在当前森林 `G_A=(V,A)` 中，取任意一个连通分量 `C`。
如果 `(u,v)` 是从 `C` 连到其他分量的最小权边，那么 `(u,v)` 是安全边。
因为可以构造割：
```
X = C 中的顶点
Y = V - X
```
这个割不会被 `A` 中的边跨越，因为 `A` 的边都在各自分量内部，所以割尊重 `A`。
而 `(u,v)` 是跨这个割的轻边，所以根据安全边定理，它安全。

1. 初始时，每个顶点自成一个树，A = ∅
2. 按边权从小到大考察边
3. 如果边 (u,v) 连接两个不同的树，就加入 A
4. 合并这两个树
5. 直到 A 有 |V|-1 条边

P算法
为什么 Prim 每次选的边是安全边
每一步看割：
```
(U, V-U)
```
当前已选边 `A` 都在 `U` 内部，不会跨越这个割，所以这个割**尊重 A**。
Prim 选的是所有跨越这个割的边中权值最小的一条，也就是这个割的**轻边**。
根据安全边定理：
```
尊重 A 的割上的轻边，一定是 A 的安全边
```

struct edge {
  int v, w;
};

struct node {
  int dis, u;

  bool operator>(const node& a) const { return dis > a.dis; }
};

vector<edge> e[MAXN];
int dis[MAXN], vis[MAXN];
priority_queue<node, vector<node>, greater<node>> q;

void dijkstra(int n, int s) {
  memset(dis, 0x3f, (n + 1) * sizeof(int));
  memset(vis, 0, (n + 1) * sizeof(int));
  dis[s] = 0;
  q.push({0, s});
  while (!q.empty()) {
    int u = q.top().u;
    q.pop();
    if (vis[u]) continue;
    vis[u] = 1;
    for (auto ed : e[u]) {
      int v = ed.v, w = ed.w;
      if (dis[v] > dis[u] + w) {
        dis[v] = dis[u] + w;
        q.push({dis[v], v});
      }
    }
  }
}

**散列表**（哈希表）
- 根据数据元素的==关键字==计算出其在散列表中的==存储地址==
- 带来的好处--查找==O(1)==---先根据散列函数求出index,然后检查
- ==冲突==的情况(两个关键字本映射到同一个index称为 同义词)，向后放
	- 减少冲突---构造更好的散列函数实现
	- 解决冲突---拉==链==法通过链表将冲突的数据==串==起来
	- 解决冲突---使用开放定址法，给元素找新的位置
- 构造更好的散列函数
	- 理解为f(x),要求定义域满足所有可能出现的关键字，意思是所有可能出现的关键字都能运算
	- 算出来的地址要合法
	- 尽可能的减少冲突，均匀分布
	- 计算尽可能的简单
- 除留余数法
	- 将关键字对p（质数）取余数
	- p取==不大于表长的==最大质数，目的是减少冲突，均匀，具体原因与公因子有关
- 直接定址法
	- H(key) = key ,或 线性H(key) = a\*key+b , 适用于关键字的分布连续的场景
- 数字分析法(没有特别均匀，需要==手工选择几位==，例如使用尾号)
	- ==选==数码分布较为均匀的若干位==作为散列的地址==
	- 例如，选择关键字中的中间几位
- 平方取中法 ==(人工构造使得分布均匀)==，目的就是不要都映射到一个地址，减少冲突
	- 取关键字的==平方值的中间几位==
