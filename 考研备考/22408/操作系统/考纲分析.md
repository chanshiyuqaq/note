- 文件元数据，不涉及文件内容的一些数据，例如文件的创建时间，拥有者，权限管理，大小，物理存储位置
- 索引节点，是一个数据结构，存储了该文件对应的物理块地址，可分为多级索引结构，其设计可能会决定文件系统能存储的最大文件的大小；文件A在目录S下面，通过读取S获得A的索引节点，然后将其读入内存，此时该索引节点同时存在于外存和内存中，==什么时候将该索引节点写回？会不会修改原本在磁盘上的索引节点的内容？内存中的索引节点与外存中的区别是什么？==

分析：如果发生了需要持久保存的元数据变化才需将变化写回，内存中的inode附加了运行时候的状态；内存inode是共享的，多个进程打开同一个文件，位置指针并不记录在内存inode中，而是在进程各自的文件打开表中，所以位置指针是独立的；


- open文件，没有将文件读入内存，==建立了fd与文件名之间的关系？fd的标号表示在进程打开文件表中的索引？进程打开文件表与系统打开文件表是如何联系在一起的？==
- read文件将文件读入内存，涉及到两次复制操作，磁盘到内核缓冲区，由内核缓冲区到用户区

fd是进程打开表的索引，进程打开表中存放偏移量(位置指针)

==文件系统在外存中的组织？==

文件系统所在卷
├─ 引导控制信息（若有）
├─ 超级块：文件系统总体信息
├─ 空闲块、空闲 inode 的管理信息
├─ inode 区域
└─ 数据区域
    ├─ 目录文件的数据块
    └─ 普通文件的数据块

分区表是磁盘层面的不涉及文件系统

- ==文件系统在内存中的组织？==

| 内存结构              | 主要作用                     |
| ----------------- | ------------------------ |
| 挂载表及内存中的==超级块信息== | 记录已挂载文件系统及其管理信息          |
| 目录项==缓存==         | 加快“目录中的名字 → 对应文件”的查找     |
| 内存 inode ==缓存==   | 保存正在使用或缓存的文件元数据          |
| 系统打开文件表           | 管理一次打开的状态，如偏移量、打开方式、引用计数 |
| 进程打开文件表           | 建立本进程 fd 与系统打开文件表项的联系    |
| 页缓存、块缓冲等          | 缓存文件内容及部分文件系统元数据         |
