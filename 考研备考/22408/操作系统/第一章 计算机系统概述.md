
# 基本概念

操作系统负责**管理硬件资源为应用程序提供运行环境** , 充当硬件与用户之间的桥梁

**四大核心功能**：文件管理(外存)，设备管理(外设)，存储器管理（内存），处理机管理

两个视角：
操作系统作为**计算机系统资源的管理者**

操作系统作为**用户**与计算机硬件系统之间的接口：
有三类用户接口：
- 联机用户接口（命令行接口）
- 脱机用户接口（作业控制语言）用户将作业控制命令写入作业说明书，连同作业一并提交；系统调度到该作业的时候，自动解释并执行说明书中的命令，无需用户实时干预。
- 图形用户接口

==程序接口：==
	核心是一组**系统调用**，早期操作系统调用基于汇编语言实现，仅能在汇编程序中直接使用。
	在高级语言中(C语言)通过标准库函数**间接**触发系统调用
	标准库函数是对系统调用的封装，有些库函数是对系统调用的封装，调用时进入内核空间，另一些可直接在用户空间实现；

操作系统的特征：
操作系统的基本特征包括：共享，虚拟，并发，异步。
- 并发与并行：
	并发指的是多个事件在**同一时间间隔**内发生。在多道程序环境下，操作系统**通过调度机制**实现多道程序的交替执行，保持CPU高利用率
	并行：指的是多个事件在同一时刻真正发生，需要多核CPU，多处理机等硬件支持 。
- 共享：指的是系统中的资源可供并发进程共同使用
	两种共享方式：
	互斥共享，保证在任意时间段内仅有一个进程访问该资源
	（打印机）
	同时访问：指的是宏观上同时访问，微观上采用分时交替方式，即分时共享
	理解：可重入代码的概念![[Pasted image 20260726214125.png]]
- 并发和共享 ==互为前提==，并发是共享的前提，**若没有并发则无需共享**；共享是并发的前提，**若没有合理的共享机制，则并发无法正常运行**
- 虚拟：
	虚拟指的是通过某种技术手段将一个物理上的实体映射为多个逻辑上的对应物。
	多道程序设计技术->每个程序仿佛独占CPU
	虚拟存储器技术->每个程序仿佛独占内存
	虚拟设备技术(假脱机==Spooling==)->每个用户独占一台逻辑设备
	原本需要互斥访问的资源可转化为可并发使用的共享资源
- 异步(Asynchronism)（主要指的是进程的异步性）：
	进程的执行以不可预知的速度断续推进
	需使用操作系统提供的同步机制

# 操作系统的运行环境

什么是==操作系统内核==：
将与硬件紧密相关的模块（中断处理程序，设备驱动程序）
运行频率较高的模块（时钟管理，进程调度）
以及各个模块共用的基础操作集中==置于内存==中，

操作系统内核的两类功能：
- 支撑功能
	时钟管理--向用户提供标准系统时间，时钟中断实现任务调度
	中断机制--==中断是现代操作系统运行的基础==，
	原语
	- 原语是一个操作，由若干条指令构成。具有原子性，常通过关中断==等手段确保不被干扰==
- 系统资源管理功能
	进程管理
	设备管理
	内存管理（存储器管理）

	严格区分操作系统代码与用户程序的运行环境，绝大多数计算机系统通过硬件支持实现区分
0表示内核态(管态)，1表示用户态(目态)。通过一个模式位标识当前当前的运行模式
	通过对指令进行分类保护，有一些指令只能在内核态执行，称为**特权指令**（可访问全部地址空间），其余称为非特权指令，可在任意模式下执行。

  用户程序通过受控方式使用内核态服务，唯一合法途径是中断/异常
  ==访管指令==(全称是访问管理程序指令)，本质上它是一条非特权指令，其唯一作用是 故意制造一个软件中断，Trap 强制CPU从用户态切换到内核态；并将控制权交给操作系统的中断处理程序
  在 x86 架构中是 `INT 0x80` 或 `SYSCALL`；在 ARM 架构中是 `SVC`
  


中断（外中断）与异常（内中断）
中断指的是来自CPU执行指令**外部的事件**，IO中断，时钟中断
异常指的是来自CPU执行指令内部的事件，地址越界，运算溢出，缺页异常

查看课本：中断与异常的分类，硬件中断与软件中断
内部异常：自陷(事先安排)，==故障(非法操作码，缺页，除0，运算溢出)==，终止(硬件故障),  非事先安排，非硬件错误都属于故障！
外部中断都是硬件中断，包括可屏蔽中断INTR和不可屏蔽中断NMI




中断和异常的处理流程：

对于中断，CPU执行完某条指令，检查中断，发现中断请求信号，关中断，保留现场，跳转到中断处理服务程序，恢复现场，开中断，执行==下一条指令==

对于异常，CPU在执行某个指令中发生，==进行处理后重新执行本条指令==。

**中断处理程序的入口地址由中断向量表提供**
- 中断向量表在==内存==中，且硬件能直接定位
- 拿到向量表基地址后，CPU==使用中断号做索引==，直接计算出对应条目的内存地址，读出中断处理程序的入口地址(不同中断的中断号不一样，==Linux的系统调用的中断号为0x80==)意思是凡是用户程序使用系统调用，触发syscall对应的中断号是x80(横向对比，时钟中断的中断号是0x20),然后执行对应的程序，进一步根据系统调用号，执行对应的系统调用的程序；
- 将其==加载到PC寄存器==，下一条就会自动执行
- 通过==中断返回指令触发硬件恢复现场== 

**访管中断**
访管中断是用户程序通过访管指令**主动请求操作系统服务**，从用户态切换到核心态执行系统调用的自愿中断。

当编译器将代码翻译成机器码的时候，==包含syscall汇编指令==的才是访管指令；
```cpp

#include <unistd.h>

int main() {
    char buffer[100];
    // read是典型的访管命令(系统调用的封装)
    // 用户程序通过此命令请求内核读取文件
    int bytes_read = read(0, buffer, sizeof(buffer)); // 从标准输入读取
    return 0;
}

```

系统调用的处理过程：
- 传递系统调用参数，用户程序将系统调用号，所需参数压入堆栈，或通过寄存器
- 执行陷入指令，切换至内核态(将PC，PSW(==硬件实现==)，及通用寄存器内容(==软件实现==))，注意这里虽然  ==实现方式不同==在X86中都是放到内核栈里

**操作系统中的通道技术**

又称为I/O处理机或I/O控制器，独立于CPU运行，能够自主管理外部设备与内存之间的数据传输，从而实现CPU与I/O操作的并行工作，极大地提高了系统的整体效率。
通道作为一个独立的处理单元，具有自己的指令系统、程序计数器和状态寄存器。它通常由三部分组成：通道控制器、通道程序存储器和数据缓冲寄存器。当系统需要进行I/O操作时，**CPU只负责启动通道和等待操作完成**，而具体的传输过程则由通道独立执行。

**PSW是什么**
程序状态字（包含特权级标志、条件码等）

**对比一般过程调用与系统调用**
系统调用的被调用过程在内核态，
一般过程调用与调用程序**运行在同一个状态**，可能是系统态，也可能是用户态
中断需要压栈PC,PSW 
一般过程调用压栈PC

**当发生中断时候由硬件完成的有**：
- PC,PSW
- CPU的模式的更改

输入输出指令指的是IO指令，==与外设交互，是特权指令==


**时钟中断服务程序工作任务详解**
- 每个进程都被分配了一个固定长度的时间片（通常为几十毫秒）。时钟中断程序负责递减当前进程的时间片计数器，当计数器归零时，触发进程调度。
- 负责维护精确的系统时间
- 进程调度触发
- 当前进程占用CPU的时间(2018统考)

# 操作系统结构

分层法：
- 便于调试，易于扩充与维护
- 易于扩充与维护
- (问题)
- 层次划分困难，运行效率低
模块化
- 追求 低内聚(指模块内) 高耦合(指模块间)
- 扩展性好，支持并行开发，可理解，可维护
- (问题)
- 接口困难，没有已验证的正确基础


宏内核：将所有的功能模块集成在一个紧密耦合的整体中，==运行在内核态，模块共享内存，减少上下文切换，消息传递开销，有性能优势==。缺点是不便于维护。

微内核：将核心内容保留在内核，非核心功能移动至用户态运行。功能==被组织为若干独立的服务程序==，运行在用户态，通过消息传递机制实现交互：
- (客户服务器模型)某一个服务崩溃不会影响其他服务，不同于宏内核(文件系统崩溃引发系统崩溃)
- 机制与策略分离，将策略交由用户态服务器实现。
- 微内核具备的功能：进程、线程管理，低级存储器管理，中断和陷入处理
优点
- 拓展灵活
- ==安全可靠==
- ==可移植==
- ==分布式==
缺点
- 性能问题，每次请求需要多次穿越内核态与用户态

外核：将物理资源暴露给用户级系统，自身仅负责资源的安全分配与隔离。
优点：减少抽象开销，提示灵活性与性能，清晰分离保护与实现

**操作系统引导**
- 指的是计算机通过执行一系列引导程序，依次  ①定位启动设备 ②确定可引导分区 ③加载其中操作系统内核 ④完成系统启动
- 具体来说 ==主板上有ROM，里存放BIOS==，即基本输入输出系统，CPU执行对应的程序(完成初始化硬件，建立中断向量表，为设备访问提供支持)
- 依据CMOS 确定启动设备有优先级，并选择首个有效的启动设备(硬盘，优盘)
- 确定了启动设备后，要找存放操作系统的对应的分区，下面介绍MBR方式
- 读取==首扇区(MBR)(主引导记录)==，BIOS读取硬盘的第0柱面，0磁道，1扇区(固定512字节)，其中包含了64字节的分区表(DPT)(理解成地图),MBR中的代码扫描这64字节，寻找主分区(活动分区)
- 找到之后，读取该分区的第一个扇区 叫做PBR(分区引导记录)
- 引导分区里有代码，，PBR 里的代码会去寻找并运行该分区根目录下的 `bootmgr`（启动管理器）文件；控制权交给存储在磁盘上的引导加载程序Bootloader（Linux）

第一类虚拟机，裸金属架构；当客户操作系统执行一条仅允许真实内核态下执行的敏感指令时，会触发异常并陷入虚拟机管理程序
第二类虚拟机，软件虚拟化；虚拟化是云服务基础；GuestOS发出的系统调用会被VMM截获转换为VMM对HostOS的系统调用


- 微内核添加新的系统服务，无需修改内核代码
- 分层式设计便于调试
- 微内核中有什么？
	- 中断相关
	- 进程调度
	- 存储器管理，（逻辑地址到物理地址的映射
	- 低级IO
- 加载系统的时候BIOS在主板上，引导阶段建立中断向量表，
- 内核初始化阶段完成==进程调度==，==内存管理==，==设备驱动==，相关操作。MBR(主引导记录) 负责确定活动分区，加载活动分区引导扇区(分区引导记录)
- 虚拟机可以通过软件实现也可以通过硬件实现
