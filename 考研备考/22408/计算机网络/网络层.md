127.0.0.1
在 IPv4 分类中，A 类网络号 `127`（即 `127.0.0.0/8` 这个巨大的网段，包含 1600 多万个地址）被全部保留，定义为“环回网段”（Loopback）。

#### 它是如何工作的？

当你在电脑上写了一个本地测试程序，让“浏览器”访问本地的“Web 服务器”：

- **目的 IP**：你输入 `127.0.0.1`（目的地址）。
- **源 IP**：操作系统会自动把源 IP 也设为 `127.0.0.1`。

#### 数据流向（闭环）：

1. 浏览器发送数据包（源：`127.0.0.1`，目的：`127.0.0.1`）。
2. 操作系统网络栈看到目的 IP 是 `127.0.0.1`，**立刻意识到这是给自己的**。
3. 操作系统**直接在内存中把数据包转弯**，送回给本地的 Web 服务器。
4. **这个数据包全程根本没有通过网线发出去，甚至都没有到达你电脑的物理网卡芯片**。它在操作系统内部就完成了“自发自收”。

==DHCP==(Dynamic Host Configuration Protocol),动态主机配置协议
是应用层协议，基于UDP
连接到互联网的计算机需要配置的项目包括：
- IP地址
- 子网掩码
- 默认网关的IP
- 域名服务器的IP地址

流程如下：
- 主机向DHCP服务器发送 ==发现报文==（广播）此时主机的原地址为0.0.0.0目的地址为255.255.255.255
- ![[Pasted image 20260927144408.png|435]]
- DHCP服务器回答 ==提供报文==，提供IP地址等配置信息
- 主机接收则广播 ==请求报文==，表示接受 (让未选中的DHCP服务器释放预留的IP地址等资源)
- DHCP服务器广播 ==确认报文==，将IP地址分配给DHCP客户，原地址为DHCP服务器地址，目的地址为255.255.255.255
- ==客户收到后配置生效==
- 有时间限制，组用期过半之后，客户发送请求报文，请求更新组用期，若DHCP服务器同意则发挥DHCP确认报文
- 组用期过87.5%后客户广播DHCP请求报文，提高续租的成功率
- 客户可以随时提前终止，只需向DHCP服务器发送DHCP释放报文

==移动IP==
一种允许移动主机在切换网络接入点时，仍能保持其永久IP不变的网络协议机制，其目标是：无论移动主机当前位于哪个网络，都能确保发往该站的数据被自动透明的投递

移动IP定义了三种功能实体
- 移动节点——拥有永久IP，可在不同网络间移动的主机
- 归属代理——连接在==归属网络==（初始接入的网络）上的路由器，负责截获并转发法向移动节点的数据
- 外地代理——连接在当前接入网络上的路由器，协助移动节点接收数据

假设使用MAC路由
- 如果用 MAC 路由，全球的路由器必须记录**每一个** MAC 地址应该往哪转。目前全球有数百亿台设备，路由器的内存会瞬间被撑爆（**路由表暴涨**），查表速度会慢如蜗牛。
- 如果网络层用 MAC 寻址，整个互联网的路由器都要紧急更新：“这个 MAC 已经去上海了，大家以后把发给它的包往上海转。”这会造成全球路由震荡。
- 并非所有物理链路都使用**以太网的 48 位 MAC 地址**。比如广域网常用的 PPP 协议、帧中继、ATM 协议，它们的**硬件寻址方式完全不同**，甚至根本没有 MAC 地址。
- 如果全球是一个巨大的 MAC 网络，一个广播包（如“谁是张三？”）将会被复制并发送给全球的每一台设备。
